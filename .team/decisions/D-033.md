## Decision

`GET /api/v1/reports/asset-results` and `GET /api/v1/reports/owner-overview` (and the legacy
`/api/reports/...` routes while they exist) require both `from` and `to` (ISO dates). Missing,
unparseable, or `to` before `from`: 400 Problem Details with `errors` per field (`from`, `to`),
from each use case's `RequestValidation.cs`. The API sets no default period; the frontend keeps
its own default (the current calendar year) and always sends both. Answers Q-056.

## Why

US-8 is "given a period", and no requirement defines a default; today a missing period silently
becomes 0001-01-01 and returns misleading zero totals. Rejected: a default period in the API (a
business rule nobody asked for, and a second default next to the frontend's); 200 with zeros.
Impact: backend 1 story point (for REQ-008), tester flips `Missing_period_...` to expect 400.
