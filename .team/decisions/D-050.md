## Decision

How D-049 is built for business rules (T-120): the Logic project throws `BusinessRuleException` with an English key (a constant, for example `OwnerService.HasAssets`), with no language of its own. `ApiExceptionHandler` returns the `detail` from `IStringLocalizer<BusinessRuleMessages>` (Dutch in `Resources/BusinessRuleMessages.nl.resx`, English is the key) in the culture of the request's `IRequestCultureFeature`: the handler runs outside `UseRequestLocalization`, so the thread culture there is not the request's. A message without a resource entry (the features not moved yet, still Dutch) is returned unchanged. Moving another feature later is: an English key in its service plus one resx entry. The request culture now comes only from the `lang` query parameter (D-049, `QueryStringRequestCultureProvider` in Program.cs); Accept-Language is ignored, the handler is unchanged.

## Why

One place for all business-rule texts, and the Logic project stays free of the web stack. Rejected: localizing in each controller or handler (error responses belong in the central handler, D-022); a resx per feature for business rules (the handler would have to know each feature); the Logic project using IStringLocalizer (ties it to the request culture).
