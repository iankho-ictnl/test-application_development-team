## Decision

1. **Package audit (REQ-028, criterion 2):** a `Directory.Build.props` in the repository root with `<NuGetAudit>true</NuGetAudit>` and `<NuGetAuditMode>all</NuGetAuditMode>`, so every restore checks the direct and transitive packages, and a known vulnerability is a build warning that is never suppressed. Backend piece B19, 0.5 SP.
2. **SDK analyzers and code style (only after Q-110):** the same file also gets `<AnalysisLevel>latest-recommended</AnalysisLevel>`, `<AnalysisModeSecurity>All</AnalysisModeSecurity>`, `<EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>` and `<Nullable>enable</Nullable>`, plus an `.editorconfig` with the code style the code already uses. Existing warnings are not hidden: B20 (0.5 SP) switches it on and lists the warnings per project in its report, and the architect then estimates the cleanup task.
3. **Coverage (REQ-028, criterion 3: fewest outside packages):** remove `coverlet.collector` 6.0.4 from the test project; coverage comes from Microsoft's own collector, which `Microsoft.NET.Test.Sdk` already brings (`dotnet test --collect "Code Coverage" --results-directory .tmp/TestResults`). Tester piece T14, 0.5 SP (T13 was taken by D-049).

## Why

Rule 17: the SDK already has the analyzers, the package audit and a coverage collector, so no outside tool is added and one is removed. Rejected: StyleCop, SonarAnalyzer and other outside analyzers (outside packages, rule 17); keeping coverlet (outside, the Microsoft collector does the same); `TreatWarningsAsErrors` now (the existing warnings are not counted yet; a decision after B20). Part 2 serves no approved requirement directly (REQ-028 is about supported versions), so it is a question to the user first (Q-110, rule 14). Replaces nothing.
