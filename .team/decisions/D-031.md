## Decision

Keep the fast suite on in-memory SQLite. Add a test collection on PostgreSQL 18 with
Testcontainers for .NET (MIT, REQ-016; needs Docker on the test machine) for what SQLite cannot
show: the migrations, `xmin` concurrency (409), the invoice-number sequence under parallel
invoicing, `numeric(18,2)` rounding and the paging limits of D-024. Tagged
`[Trait("Category", "PostgreSql")]`, skipped with a clear reason when Docker is absent. REQ-022
performance tests: `[Trait("Category", "Performance")]`, fictitious seven-year data set, run only
on request in the environment the user approves (Q-052), never in the normal run.

## Why

All API tests run on SQLite while production runs PostgreSQL 18: D-024 (T-039) behaviour and the
REQ-022 index and timing criteria cannot be verified there. Rejected: everything on PostgreSQL
(slow, Docker needed for every run); a shared test database (state leaks between runs). Impact:
tester, 3 story points after T-039; Testcontainers package version to be checked by the architect.
