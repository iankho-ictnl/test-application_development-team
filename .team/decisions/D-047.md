## Decision

One demo test class per sprint (`PropertyAdmin.Tests/Demo/S2DemoTests.cs`, `[Trait("Category", "Demo")]`) walks the demo steps of `plan.md` in order. It follows the D-030 harness (real Razor pages, forms posted with their antiforgery token; its own `DemoStack` and `Browser` in `Demo/`, because `FrontendFactory` is tied to the SQLite API and is not on the item's branch, T-125 review) and the real API host, with the API on a fresh PostgreSQL 18 container (Testcontainers, D-031) migrated by the normal migrations and seeded by the normal seed admin from test configuration (no password in the code). It signs in through `/Account/Login` with that account, and repeats the checks in Dutch and English through the culture switch. The invoice PDF is read with PDFsharp (already in, D-017). It runs in every `dotnet test`; without Docker it fails with the message "the demo test needs Docker Desktop" (it is never skipped). No browser: the S2 demo has no step that needs JavaScript.

## Why

Uses what the solution already has: no new package except Testcontainers.PostgreSql (4.17.0 on nuget.org on 2026-11-20, MIT, maintained by the Testcontainers project; .NET has no built-in way to start a container; the security officer checks its known vulnerabilities with `dotnet list package --vulnerable`), already accepted in D-031 but now, under rule 17, it needs the security officer's review and the user's OK (Q-104). Rejected: Playwright against the running docker compose stack (outside tool with downloaded browsers, T-030 is on the cut list, and it would write test owners into the user's own data volume); a hand-made `docker run` from the test (re-builds Testcontainers badly); SQLite (not the real database). Known gap: client-side JavaScript is not exercised; a later demo step that needs it is a question to the user (T-030). Impact: tester, T-112.
