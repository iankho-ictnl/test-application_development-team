## Decision

All four projects move from `net8.0` to `net10.0` in one step. The ASP.NET Core and
EF Core packages go to 10.0.14, Npgsql and its EF Core provider to 10.0.3, the `dotnet-ef` tool
to 10.0.14. A new `global.json` in the repository root selects the newest installed .NET 10 SDK
(roll forward to the latest feature band) and never a preview SDK. Impact:
- **Code.** `test application for development team/Program.cs`: `ForwardedHeadersOptions.KnownNetworks`
is obsolete in ASP.NET Core 10 (warning ASPDEPR005); use `KnownIPNetworks` (what it contains:
question 24). `PropertyAdmin.Api/Program.cs`: OpenAPI as in decision #16. The token code
(`TokenService`, `SignInService`) only needs a recompile (decision #13). The PDF font resolver is
the project's own `IFontResolver`, so the PDFsharp 6.2 change (built-in Core font resolver
removed) does not affect it.
- **Database code.** Since EF Core 9, `MigrateAsync` at start-up throws when the model has changes
that no migration covers, and it locks the database while it migrates. After the upgrade, run
`dotnet ef migrations has-pending-model-changes`; if it reports changes, add a migration (do not
suppress the warning). Npgsql 9 and 10 change nothing that this model uses (no PostgreSQL enums;
dates are already `DateOnly`). Connections are now recycled after 1 hour by default. Npgsql 10
may log a harmless message that `libgssapi_krb5.so.2` (Kerberos) cannot be loaded.
- **Packages.** As in Technology versions. The .NET 10 SDK audits transitive packages on restore;
every reported vulnerability is fixed, not suppressed.
- **Images.** Decision #14. `docker-compose.yml` needs no change for .NET.
- **Tests.** The test project moves to `net10.0` and xUnit v3 (decision #19); the tester runs the
regression check of task U6.

## Why

.NET 8 support ends on 2026-11-10 and the user asked for .NET 10 (question 18). .NET 10
is the release with the latest end of support (LTS, 2028-11-14). Rejected: .NET 9 (STS, support
also ends 2026-11-10); .NET 11 (not released). Rejected: upgrading project by project; the four
projects are small (about 6,000 lines) and share `PropertyAdmin.Contracts`, so one pass is shorter
and avoids mixed target frameworks.
