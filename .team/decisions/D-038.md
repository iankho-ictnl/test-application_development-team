## Decision

The target architecture stays (REQ-017, REQ-023, REQ-025 are approved): one Linux host with Docker compose. Because the user's laptop has no Docker and there is no server yet (Q-064):
- The normal `dotnet build` and `dotnet test` need neither Docker nor PostgreSQL: SQLite and the in-memory hosts (D-011, D-031 fast suite, REQ-030 screen tests). Tests that need PostgreSQL (D-031 collection) are left out of the normal run and are skipped, never failed, when no database is reachable; with xUnit 2 kept (Q-070) the tester picks the skip mechanism.
- Everything that needs a Docker host is reported as "built, not verified" (testing.md, report) until it has run: REQ-017 (`docker compose up`, data kept), REQ-025 and D-023 (only 80/443 published, valid Let's Encrypt certificate), D-024 (migrations as `propertyadmin_migrator`, app as `propertyadmin_app`), REQ-023 (a backup run and the first restore test, `deploy/backup/RESTORE-TEST.md`), REQ-022 (T9), C6 and S-27 deployment notes.
- These checks become one go-live verification task (tester with the user) when a Docker host exists; where and when follows Q-078 and Q-079. `docker-compose.yml`, `Caddyfile` and `deploy/` stay as built.

## Why

No design part depends on the laptop, so no architecture change is needed; only where the checks run changes. Claiming these as tested without a Docker host would break RULES rule 11. Rejected: SQLite or Windows services as the production target (REQ-017 asks for compose); dropping the PostgreSQL tests (`xmin` 409 and the invoice sequence of D-024 cannot be shown on SQLite). Details: architecture.md, "Development and test without Docker". Cost: the go-live verification, about 2 story points, plus whatever Q-078 chooses.
