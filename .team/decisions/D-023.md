## Decision

Production compose gets a `proxy` service (official `caddy:2` image, Apache-2.0)
as the only service with published ports (80 redirect, 443). It terminates TLS with a
certificate from ACME (Let's Encrypt) for the public host name (Q-035: the frontend is public,
Let's Encrypt; the host name is not known yet and is set through the `PUBLIC_HOST` environment
variable, so no code change is needed when it is known), forwards to `web:8080` and sets `X-Forwarded-For` and
`X-Forwarded-Proto`. `web` no longer publishes port 8080 in production. The compose network
gets a fixed subnet (`172.30.0.0/24`) and the proxy a fixed address `172.30.0.10`; the frontend
reads `ForwardedHeaders:KnownProxies` (`172.30.0.10`) from configuration and trusts forwarded
headers only from there (S-15). `api` and `db` publish no ports in production and are only
on the internal compose network (REQ-025, Q-035). Development keeps plain HTTP on the Visual Studio profile.

## Why

S-16 (question 31): cookies are `Secure` and HSTS is on, but nothing serves HTTPS.
Caddy renews certificates automatically and is free (REQ-16). Rejected: Kestrel with a
certificate (manual renewal, certificate inside the app container); nginx (no automatic
ACME). Impact: compose, a `Caddyfile`, frontend configuration; 2 story points (U7).

Accepted by the user, 2026-11-09.
