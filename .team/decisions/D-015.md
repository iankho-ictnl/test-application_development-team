## Decision

docker compose uses `postgres:18-trixie`. The PostgreSQL 18 image keeps its data in
`/var/lib/postgresql/18/docker` and declares its volume at `/var/lib/postgresql`, so the `pgdata`
mount moves from `/var/lib/postgresql/data` to `/var/lib/postgresql`. The image documentation
warns that data is not kept when the container is re-created if the volume is mounted at the old
path. A new major version cannot read the data directory of an older one, so existing data needs
a dump and restore (or `pg_upgrade`); which procedure applies depends on question 20. This runs
after the .NET 10 upgrade.

## Why

18 is the supported version with the latest end of life (2030-11-14; 17: 2029-11-08;
16: 2028-11-09). Npgsql supports all supported PostgreSQL versions. The Debian 13 (`trixie`)
image has the longest OS support (Debian LTS until 2030-06-30), and naming it in the tag keeps
the OS fixed. Rejected: staying on 16 (ends 2028-11-09); 17 (one year less, same migration work);
the Alpine variant (other C library, no benefit here).
