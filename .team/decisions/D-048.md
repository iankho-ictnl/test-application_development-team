## Decision

The frontend's ApiClient takes a failed call's message from the Problem Details `detail` first, then the `title` (D-022: the API puts the business-rule reason in `detail`). ApiPageModel.AddApiError looks that message up in the resource files: a known Dutch API message (keyed by its exact Dutch text, for example "Eigenaar heeft nog objecten en kan niet worden verwijderd.") shows in the user's language; an unknown one shows as the API sent it. BUG-10, T-113.

## Why

The API's business-rule messages are Dutch only, while the screen also runs in English (REQ-011). Rejected: a frontend message per status code (that is business logic in the frontend and loses the reason); changing the API to send codes (a contract change, not needed for this bug). Consequence: when the backend changes the text of a business-rule message, the English resource entry must change with it, or the Dutch text shows.
