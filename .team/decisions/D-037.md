## Decision

Replaces D-026 (until 2026-11-11 also D-030, see the amendment below). The user stopped D-026 where it is (Q-075 b, 2026-11-10):
- Backend stays as built (T-032 to T-036): V1 slices in `PropertyAdmin.Api`, `PropertyAdmin.Logic`, `PropertyAdmin.Data`; no reference to `PropertyAdmin.Contracts`.
- Frontend keeps `Services/ApiClient.cs` and `PropertyAdmin.Contracts` (now used only by the frontend and the tests) and keeps calling the unversioned `/api/...` routes. These stay as extra route attributes on the V1 controllers as long as the frontend uses them (Q-045's "until T-037/T-038" no longer applies); `/api/v1` is served next to them.
- Every API contract change (for example D-036) updates the matching `Contracts` type in the same item, by frontend-developer-1, with an API test on the `/api` route.
- Existing tests stay where they are; new tests follow D-027 (traits, `V1/<Feature>/<UseCase>/` for new backend tests).
- Dropped: T-037 (5), T-038 (3). Replanned: architecture.md, Build task list.

Amended 2026-11-11 (T-065, Q-076): D-030 is not ended. The user keeps it as regression tests of the admin screens (REQ-030); T-057 (3) stays, no longer a safety net for T-037 but part of every normal test run (D-038). Until this amendment D-037 also ended D-030 and dropped T-057.

## Why

The user's choice (Q-075 b): no approved requirement asks for the layout, and 11 story points are saved. Deviations from the layout rules that remain (D-026 list): 8 (all frontend models in one `Dtos.cs`), 10 (no API client or mapping per feature in the frontend), 11 (the frontend uses unversioned routes), 12 (existing tests not mirrored). Risk: the `Contracts` types and the API's V1 models are kept in step by hand; the rule above and the API tests on `/api` contain it. Rejected: new frontend-owned models only for new or changed calls (a third style next to `Contracts`); removing the `/api` routes (breaks the frontend).
