## Decision

BUG-13 is fixed in the backend by backend-developer-1 (0.5 story point, branch bug/BUG-13-profile-sign-out). In `AuthService.GetTwoFactorAsync`, when the user has no authenticator key yet, the key is created with `GenerateNewAuthenticatorKey` and stored through the authenticator key store and `UpdateAsync`, not with `ResetAuthenticatorKeyAsync`, so the security stamp stays the same. `ResetAuthenticatorKeyAsync` (with its stamp change) stays for an existing key: the Admin reset (`reset-2fa`) and `2fa/disable`. The frontend is unchanged. The tester (0.25 story point) turns the BUG-13 test into the expected behaviour (still signed in after /Profile) and drops the "visit /Profile last" workaround. The security officer reviews the change in its pull request.

## Why

A read (GET) should not end the user's session; the stamp change does nothing for security here, because two-factor sign-in is off and no key existed, so there is no older key or session to revoke. Rejected: the frontend signs in again or renews its token after the call (works around a side effect it does not own, and every other client would hit it too); creating the key at account creation (changes user creation and the Admin reset for the same result).
