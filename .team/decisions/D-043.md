## Decision

Interface contract: enums (`type` AssetType, `kind` ActivityKind, `pricingType` PricingType and any other) travel as numbers in requests and responses, as the API does today. (1) Frontend (frontend-developer-1): `ApiClient` no longer writes enums as text: remove `JsonStringEnumConverter` from its `JsonSerializerOptions` (reading numbers needs no converter). (2) API (backend-developer-1): `AddControllers().AddJsonOptions(o => o.AllowInputFormatterExceptionMessages = false)`, so an unreadable body gives the normal 400 validation Problem Details with a generic message per JSON path (`$.type`: "The input was not valid.") and never a .NET type name or exception text (D-022). Tests: an API test posting `type: "Home"` gets 400 `application/problem+json` whose body does not contain `PropertyAdmin` or `could not be converted`; a frontend test that `ApiClient` sends enums as numbers.

## Why

The contract in use is numbers: the API's V1 models and the characterization tests (`type = 0`, `kind = 1`) fix it, and D-037 makes the frontend's `Contracts` follow the API, not the reverse. Rejected: `JsonStringEnumConverter` in the API (changes every response for all clients and the characterization tests; readable, but no requirement asks for it); a custom `InvalidModelStateResponseFactory` (more code for the same result as the built-in switch).
