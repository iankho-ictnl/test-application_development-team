## Decision

Owner and Asset get `Street` (200), `HouseNumber` (20, with addition, for example "12A"), `PostalCode` (20), `City` (100) and `Country` (100, free text), all required, trimmed, not empty. Owner also gets `KvkNumber` (optional; when given, exactly 8 digits) and `VatNumber` (optional; spaces and dots removed, upper case, then any EU VAT number format (Q-088): one of the 27 member-state prefixes (Greece `EL`) followed by 2 to 12 letters or digits, and for the prefix `NL` exactly 9 digits + `B` + 2 digits). The address accepts foreign addresses (Q-088): no field is checked against a Dutch format. The invoice PDF shows the owner block, read from the current owner record, not a copy (Q-089 a): name; street and house number; postal code and city; country; `KvK:` and `Btw-nr:` only when filled. One migration per entity (owners in S2, assets in S3) renames `Address` to `Street` (data kept) and adds the new columns as `NOT NULL DEFAULT ''` (nullable for KvK and BTW). Details: architecture.md, Database architecture and Build task list (Q-087).

## Why

Separate fields, as the user asked (Q-087), instead of one free-text address. Country as free text, like the other address parts, instead of a fixed list: no list was asked for and none exists in the code. Rename instead of "add first, remove later": no version is deployed (Q-079), so no running API needs the old column; only laptop test data exists, which the rename keeps. Existing rows get an empty house number and country, and saving them again asks for both. Rejected: parsing the house number out of the old address (unreliable for free text). VAT number: prefix plus a general length check instead of one pattern per member state, because the user asked to accept every EU format, not to verify it, and 27 patterns need upkeep; the Dutch pattern stays for `NL` (Q-087). Prefixes: Your Europe, "Check a VAT number (VIES)", checked 2026-11-20. Not checked against VIES (no other system, Q-051). Rejected: an invoice copy of the owner data (Q-089 b, about 2 story points; the user chose no).
