## Decision

Built in T-127 (B18) under D-049. Each `[Required]`, `[EmailAddress]` and `[MaxLength]` on the owner requests sets `ErrorMessage` to an English key (constants in `OwnerMessages`: "This field is required.", "This is not a valid email address.", "This field can contain at most {1} characters."); the Dutch text is in `OwnerMessages.nl.resx`. `AddDataAnnotationsLocalization` uses the `OwnerMessages` resources for every type. Attributes without `ErrorMessage` (all other features today) keep the framework's English defaults. The messages name no field: the `errors` key already names it, and a Dutch sentence with an English property name reads badly. When the next feature is localized, rename `OwnerMessages` to a shared validation messages class. **Condition met (T-140, commit c7d3799, 2026-11-20):** the texts live in `PropertyAdmin.Api/Validation/ValidationMessages.cs` with `Resources/Validation/ValidationMessages.nl.resx`, outside the version folders, used by the owner and asset requests; the owner-only KvK/BTW check moved to `V1/Owners/OwnerNumberValidation.cs`.

## Why

For record constructor parameters MVC calls the localizer provider with the parameter's own type (`string`), not the request type, so choosing a resource per feature does not work (tried first: the Dutch texts were not found). Rejected: `ErrorMessageResourceType` (needs a generated resource class per resx), validation by hand in `RequestValidation` (duplicates the attributes).
