## Decision

The frontend sets on every response (middleware right after forwarded headers, so static files and errors get it too): `Content-Security-Policy: default-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`. Pages have no inline script, event handlers or style attributes; behaviour comes from `site.js` through `data-confirm` (delete confirmation), `data-autosubmit` (select sends its form) and `data-pricing-toggle` (activity pricing fields). A test scans all pages for inline script.

## Why

The policy without `'unsafe-inline'` stops injected script even if output escaping fails somewhere. Nonces were rejected: more code in every page for the same result on a site that needs only three small behaviours. The headers in Caddy instead were rejected: the frontend then has no protection when run without the proxy (laptop, tests). The confirm text now sits in an HTML-encoded attribute instead of a JavaScript string, which also removes a quoting risk.
