## Decision

The role management endpoints (`GetAll`, `Create`, `Update`, `Delete`) become their own V1 feature `Roles`
with route `/api/v1/roles` (legacy `/api/roles` kept as Q-045 says), next to the feature `Users`
(`/api/v1/users`). D-026 lists the features without Roles; this adds it. The check "at least one active
user keeps user management" (`UserAdminGuard`) is shared by both features and moves to the Logic
project's root, like `Money.cs`. Same permission (`Users`) and behaviour as before.

## Why

The role endpoints have their own resource and route; one thin controller per feature (D-026) rules
out a second controller in `V1/Users/`. Rejected: roles under `/api/v1/users/roles` (changes the
interface contract for the frontend, T-037); a second controller inside `V1/Users/` (breaks one
controller per feature).
