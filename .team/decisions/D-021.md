## Decision

Restructure `PropertyAdmin.Api` to `Features/V1/<Feature>/<UseCase>/` (for example
`Features/V1/Invoices/CreateInvoice/`), each use case with its request, response, handler and
validator. Commands (change data) and queries (read only, `AsNoTracking`, projection to the
response) are separate handlers. Controllers or endpoints are thin: map the HTTP request to the
command/query, call the handler, map the result to HTTP. Business logic stays in services
(`VatService`, `InvoiceService`, `ReportService`) or handlers, never in controllers. Mapping
at every boundary: entities never leave the API; contracts DTOs are mapped explicitly per use
case (replaces the shared `Services/Mapper.cs`). Routes get a version: `/api/v1/...`; the
frontend `ApiClient` follows.

## Why

Found in task 13: `MasterDataControllers.cs` (3 controllers) and
`TransactionControllers.cs` (4 controllers) use `AppDbContext` directly, mix reads and writes,
map in controllers, and routes have no version. Impact: API files move and split, no database
change; frontend `ApiClient` routes change; tests per handler. 8 story points (B4 API, 1 of
them F4 frontend routes). Rejected: MediatR (licence changed to commercial in 2025; REQ-16).
