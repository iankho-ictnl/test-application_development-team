## Decision

Replaces D-038. The architecture stays (one Docker compose host). Docker Desktop is on the laptop (Q-078) and going live is out of scope (Q-079), so:
- The app runs on the laptop with `docker compose up` from a local `.env` (fictitious secrets, `PUBLIC_HOST=localhost`); Caddy then serves `https://localhost` with its own local certificate (the browser warns once). No compose file per environment, no published port besides the proxy.
- The PostgreSQL tests (D-031, T8) use Testcontainers on the laptop's Docker; when Docker is not running they are skipped with a reason, never failed. The normal `dotnet test` (SQLite, in-memory hosts, REQ-030) still needs no Docker.
- Checked on the laptop: REQ-017 (start, data kept), REQ-023 (a backup run and the restore test), REQ-025 (only 80/443 published, HTTP to HTTPS, forwarded headers), D-024 roles and migrations, REQ-022 paging and query plans.
- Not checkable without a production host, reported as "built, not verified": the Let's Encrypt certificate for a public name (REQ-025), the REQ-022 timing run on the production host (Q-082), the REQ-027 hosting costs. The go-live verification task of D-038 is dropped.

## Why

Q-078 and Q-079 remove both reasons for D-038 (no Docker, a server to come). Running the real compose on the laptop checks most of what D-038 postponed at no extra cost. Rejected: a compose override that publishes `web` on a port (a second path past the proxy, REQ-025); a GitHub Actions pipeline (new scope, needs a requirement). Details: architecture.md, "Development and test on the laptop".
