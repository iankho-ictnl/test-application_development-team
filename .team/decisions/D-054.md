## Decision

The root `.editorconfig` gets one section `[PropertyAdmin.Tests/**.cs]` with `dotnet_diagnostic.CA1707.severity = none` and `dotnet_diagnostic.CA1711.severity = none`; product projects keep both rules. CA5350 stays on everywhere; the one TOTP test helper line gets `#pragma warning disable/restore CA5350` with the reason (RFC 6238 authenticator codes use HMAC-SHA1). The other 53 warnings of T-136 are fixed in B21, F9 and T15 (1.75 story points, within the Q-111 cap of 2). The frontend namespace `test_application_for_development_team` (1 × CA1707) is not renamed: the tester lists it in `testing.md` as a known warning. Details: `architecture/build-tasks.md`, "Warning clean-up".

## Why

D-027 names tests `Method_condition_result`; renaming 260 tests costs far more than 2 points and gains nothing. xUnit requires `[CollectionDefinition]` classes, usually named `...Collection`. Scoping to the test project keeps both rules for product code. Rejected: renaming the tests (cost), a global suppression (hides product warnings), turning CA5350 off for the test project (would hide a real weak-hash use later). Renaming the frontend namespace touches every frontend file for one warning.
