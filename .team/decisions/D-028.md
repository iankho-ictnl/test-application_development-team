## Decision

One data-driven test (xUnit theory) per row of the authorization matrix in architecture.md:
for each policy, one representative endpoint per action, called by each role (Admin, Manager,
Staff, Finance, Viewer, Owner, and a user with Staff + Finance for the union of REQ-012); allowed
is 2xx, not allowed is 403. Token tests on a protected endpoint: none, malformed, wrong signature,
expired, challenge token used as access token, revoked (security stamp, locked out) are 401.
An enumeration test (REQ-019) reads every endpoint from `EndpointDataSource` and fails when one
has no policy beyond the fallback, except login and login-2fa. Owner isolation on every read
endpoint, including uninvoiced lines, PDF and reports. Admin reset of 2FA ends the user's token
(REQ-013). Tests written against `/api/v1`, after T-036.

## Why

Today each endpoint group tests one forbidden role and anonymous 401 only: Manager, Finance and
Viewer rights are mostly untested, expired and wrong-purpose tokens are untested, the REQ-019
enumeration test does not exist, and Owner isolation misses uninvoiced lines and reports.
Rejected: one hand-written test per endpoint and role (about 300 tests, hard to keep in step with
the matrix). Impact: tester, 3 story points; expected result for permission removal waits for Q-049.
