## Requirement

Every build checks the code with the .NET SDK's own analyzers (recommended rules, security rules, code style, nullable) and reports the warnings (user, Q-110, 2026-11-20)

## Acceptance criteria

- Given the solution, when `dotnet build` runs, then the SDK's recommended and security analyzers, the code style rules from `.editorconfig` and the nullable checks run on every project, with no outside analyzer package (rule 17, D-051).
- Given a build, when a check finds a problem, then it is listed as a warning in the build output; no warning is hidden by a blanket suppression.
- Given the warnings the first build reports, then the architect estimates their clean-up as a task in a sprint.
