## Requirement

At most 24 hours of data loss (recovery point objective, RPO) and at most 2 days to restore
(recovery time objective, RTO), with a daily backup. The database and its backups are on the
same production host; the user accepts that losing the host also loses all backups (Q-039).
There is no off-host backup copy in the current scope.

## Acceptance criteria

- Given the production compose, when a day passes, then a `pg_dump` (custom format) of the
  database and a copy of the data-protection keys exist with that day's date on a backup volume
  separate from the database volume, on the same host, and backups older than the retention
  period are removed.
- Given a backup failed, when the next check runs, then the failure is visible (logged as an
  error and shown to the administrator); it is never silent.
- Given an empty host with Docker and the latest backup, when the documented restore procedure
  is followed, then the system works again with the data of that backup within 2 days (restore
  test at least every quarter, result recorded).
- Given the production host is lost, then the database and all backups may be lost; this risk is
  accepted and there is no off-host copy in the current scope.
