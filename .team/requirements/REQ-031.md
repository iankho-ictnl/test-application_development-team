## Requirement

A short deployment README in the repository: set-up, .env variables, starting the app, backup and restore (user, Q-084, 2026-11-11)

## Acceptance criteria

Recorded by the architect on 2026-11-11 (Q-085) from Q-084; the user still confirms them. One short `README.md` at the repository root, no second guide and no documentation system (1 story point, S10).
- Given a laptop with Docker Desktop and a fresh clone of the repository, when a person follows only the README (copy `.env.example` to `.env`, fill in their own values, `docker compose up -d --build`), then `https://localhost/Account/Login` shows the sign-in page and the seed admin can sign in.
- Given `.env.example`, then the README names every variable in it with its purpose and whether it is required, and contains no value of a secret (REQ-020); it says where a public deployment differs (`PUBLIC_HOST` set to the public name, DNS pointing at the host, ports 80 and 443 open, so Caddy gets the Let's Encrypt certificate, REQ-025).
- Given the running app, when a person follows the README's backup part, then they find where the daily backups are kept (the backup volume, 14 daily and 12 monthly) and that they stay on the same host (REQ-023, Q-039); when they follow its restore part into an empty compose project, then the restored app shows the same owners as before the backup.
- Given the end of the project, then the README lists what is built but not verified (D-039): the Let's Encrypt certificate for a public name, the REQ-022 timing run on a production host, and the REQ-027 hosting costs.
